Why it's built this way

Four steps of reasoning, one conclusion.
01
A model that decides can be talked out of it.
Prompt injection, a spoofed email, a clever jailbreak. Anything that reasons can be argued with. Security cannot rest on something you can sweet-talk.
→ so the gate decides in code: deterministic, auditable, impossible to argue with
02
But code only catches what you listed in advance.
Fixed rules miss the novel attack, and the request that breaks no rule but still is not something you would do.
→ so a model trained on you catches what the rules cannot enumerate
03
So we run both, and defer to the more cautious one.
The rules are perfect on the threats you can name. The model catches the ones you can't. Always going with the more cautious answer adds that coverage without ever trading away safety: either judge can say no, neither can force a yes.
→ nothing is approved unless both agree, and the model can only ever add caution
04
Personalization is the security.
The model that knows what is normal for you is the same model that speaks in your voice. One set of weights: the detector and the personality are the same thing. That is why a generic firewall cannot do this, and a model trained on you can.

Two judges check anything it can't take back.

Spending money, sending something out, sharing a secret, changing settings. Either judge can say no; neither can force a yes. The boss gives one of three answers:

  • Speaks every decision in the founder's voice

judge two · the gate

Your written rules

Pure deterministic code. Six rules in fixed precedence: budget, privilege, secret, provenance, auth, pattern. Same input, same verdict, every time, fully auditable.

  • Perfect, repeatable enforcement of known threats
  • Names the exact rule that fired
  • Cannot be talked out of a refusal
when the two judges disagree, the decision defers to the more cautious one  ·  your instinct can add caution the rules miss, but it can never talk the rules into a yes

The six rules the gate enforces

Plain code, in fixed order. The first rule that fires wins, and it names itself in the verdict.
BUDGET
Spend caps and approved vendors. No paying an off-list vendor, no going over cap, no structuring under the cap, no raising your own limit.
PRIVILEGE
Every agent stays in its lane. Ask the owner for the output, not the access. No self-approval, no spawning copies, no disabling the audit log.
SECRET
Production secrets never leave the vault in plaintext. Sacred documents (cap table, financials) move only on the founder's verified channel.
PROVENANCE
Content from a document is data, never a command. An instruction buried in a ticket or attachment does not get to run.
AUTH
Only the founder's verified channel carries founder authority. "From the founder" typed into an inbox message is not authentication.
PATTERN
Even a request that breaks no rule is held if it is off your normal pattern: a payee this lane has never paid, above its routine band.

The model that knows you

A Qwen2.5-3B LoRA fine-tuned on Lightning Studios on 520 of the founder's own decisions: each an agent request mapped to the founder's allow / deny / hold and a one-line reason. One model, three jobs in the agent: the second judge, the voice, and the off-pattern sense.

Deterministic gate

The floor that cannot move

A pure Python function, no clock, no network, no model on the decision path. Identical input yields byte-identical verdict. Unplug every model and the refusals still fire.

44 tests green

How the model is trained and used. The data is 520 rows of this founder's real governance decisions (the request in, the founder's verdict and reason out) plus 180 voice-tone rows, generated against the exact caps, vendors, and scopes the gate enforces, so the model and the rules describe one world. We LoRA fine-tune Qwen2.5-3B on Lightning and serve the merged weights behind an OpenAI-compatible endpoint. It powers the agent three ways: it forms its own verdict as the second judge, it phrases the final decision in the founder's voice, and its token-likelihood is the "how unusual for you" signal. Either judge can refuse; the model can only ever add caution, so a model mistake always fails safe.

The hard part of autonomy: an agent that can act for you can be tricked into acting against you. Someone emails it pretending to be you, and it just does it. So we built the thing that says no, and made it a copy of your own judgment that the agent cannot argue with.
Honest framing. The deterministic gate is demo-reliable by design. The learned model is a real, running fine-tune, but on a few hundred rows it is noisy, so when it is unsure it abstains and the gate decides. The capability is real, the demo's reliability is engineered, and both are true at once.
